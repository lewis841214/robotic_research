# Paper card reference

## Commands

From the repository root:

```bash
python .cursor/skills/paper-card/scripts/paper_card.py fetch-pdf URL corpus/papers/<id>/paper.pdf
python .cursor/skills/paper-card/scripts/paper_card.py clone URL corpus/papers/<id>/repo
python .cursor/skills/paper-card/scripts/paper_card.py index corpus/papers/<id>/repo corpus/papers/<id>/extracts
python .cursor/skills/paper-card/scripts/paper_card.py validate corpus/papers/<id>/card.json
python .cursor/skills/paper-card/scripts/paper_card.py render-example corpus/papers/<id>/extracts/<name>_example.json corpus/papers/<id>/extracts/<name>_example.mp4
python .cursor/skills/paper-card/scripts/paper_card.py site corpus
```

`clone` refuses an existing directory. `fetch-pdf` checks the `%PDF` header. `validate` checks the schema and rejects a `verified` claim with no source. `site` rewrites `corpus/site/` and `corpus/index.jsonl`.

## Run the flows

After `clone` and `index`, run the paper model's inference entry, then its training entry. A toy or demo that builds a different config does not replace that entry. Skip both only when `repo_role` is `none`, and say so in `model.runtime`.

Load the token without echoing it. `huggingface_hub` also reads `HUGGING_FACE_HUB_TOKEN`.

```bash
set -a
source /mnt/d/robotic_research/.env
set +a
export HUGGING_FACE_HUB_TOKEN="${HF_TOKEN}"
```

Install the packages that entry imports. Inference is one prediction of the paper model, using the checkpoint the README names when that download fits locally. Training goes far enough for one optimizer step on the paper's loss. When the documented schedule is long, keep the same entry point and set its own step flag to 1 or 2. Say that in `model.runtime`.

Save stdout and stderr, with the token string removed, to `corpus/papers/<id>/extracts/run_infer.txt` and `corpus/papers/<id>/extracts/run_train.txt`. Put the command and the exit code at the top. A number printed there is `verified` with source kind `run` and that file as the locator. A number the run did not print stays `missing`.

## Card rules

`id` is lowercase letters, digits, and hyphens.

Identity comes first. Record authors, venue, arXiv id, PDF URL, project URL, repository URL, and the commit that was cloned. `repo_note` says what that repository is. `distinct_from` lists similarly named works that must not be merged.

`landscape` copies the row from `docs/corl_2026_paper_list.md` that motivated the card: paradigm, bottleneck, and the RTX 5070 Ti feasibility note. Those strings are the user's landscape labels, not measurements from the paper.

Data fields are name, dtype, and shape. A shape taken from prose is `tier: paper`. A shape read from a dataloader is `tier: code`. A shape measured from an opened sample is `tier: loaded`. Say which one in `data.note`. The viewer draws the field table; it does not invent images.

Model modules name the block, the stated parameter count when one exists, and a code anchor when the class was opened. `model.runtime` records the inference command, the training command, the device, and whether each exited. The AST outline beside the card is generated by `index` and is not a parameter census.

Compute facts are device, precision, batch, steps, wall time, and control rate, each on its own row. A missing GPU stays a gap.

An objective stores LaTeX without delimiters, a short explanation, a symbol list, and the function that implements it when that function was opened. If the formula is only in the PDF, `code` is empty and the source points at the equation number.

A procedure step is one algorithmic line. Train and infer are separate lists. Each line that was matched to code has a `path`, `start`, `end`, and a GitHub URL pinned to `repo_commit`:

`https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<start>-L<end>`

`gaps` lists what this pass could not verify: no public PDF, no public training code, runtime import not run, a number the paper does not state, or no checkpoint-aligned example clip.

## Training data

`data.training_provenance` is required. `mode` is `sim_policy_rollout`, `recorded_success`, `both`, `reference_only`, `synthetic_other`, or `unknown`. The summary says which streams enter the loss.

Each dataset sets `stream_kind` to `simulation`, `recorded`, `teacher`, `synthetic`, or `mixed`, and `feeds_gradient`. A simulation dataset has `simulator` (name, env id, collector). A recorded dataset has `recorded` (origin, dataset name, success filter). A mixed dataset has `mixture`. `golden.kind` is the training target: `expert_action`, `action_chunk`, `reference_motion`, `next_state`, `reward_return`, `goal_image`, or `none`.

A dataset with `feeds_gradient: true` has `example`. `example.shows` is `observation`, `trained_checkpoint_action`, `golden`, in that order. The trained checkpoint's action is required on every verified frame. A clip that was not rendered is `status: missing`, with `view: none`, null paths, and a note naming the missing checkpoint action. `inferred` is not used for this field.

A verified example is at most 128 frames. `video_path` and `sidecar_path` live under `extracts/`. `trained_checkpoint.checkpoint_path` is a file inside the paper directory. The sidecar is:

```json
{
  "fps": 50,
  "frames": [
    {
      "t": 0,
      "time_s": 0.0,
      "image": "frames/000.png",
      "observation": "what this frame shows",
      "trained_checkpoint_action": [0.1, -0.2],
      "golden": {"kind": "action_chunk", "summary": "logged action", "values": [0.0, -0.1]}
    }
  ]
}
```

`image` is required for `sim_rgb` and `camera`, and is relative to the sidecar's directory. `plot` may omit it. Frame `t` equals the list index. `trained_checkpoint_action` has length `trained_checkpoint.dim`. `golden.values` is present when the target is a vector that can be drawn.

`render-example` writes the mp4 from that sidecar. Frame `i` of the video is sidecar frame `i`. The left pane is the observation. The right pane draws the checkpoint action in green and `golden.values` in amber. `validate` checks the sidecar and that `ffprobe` reports `num_frames`.

## Parts

`task` is the method's operating contract: embodiment, action semantics, horizon, contact, latency, and data volume. A new task is matched against this contract before any slot is reused.

`parts` has these slots, in this order, on every card:

1. `observation_encoder`
2. `language_or_goal`
3. `memory`
4. `action_representation`
5. `controller`
6. `objective`

Each slot records the choice, inputs, outputs, what stays frozen, what is trained, and `breaks_if` — the assumption that makes the swap fail. `evidence.claim` is the paper's comparison or ablation of that slot. `evidence.status` is `verified` only when the cited source compares that slot. A full-system number with no slot ablation is `missing`, and the claim says so. `site` writes the cross-paper matrix to `corpus/site/parts.html`.

## Batch

`corpus/manifest.yaml` is the input list. One card directory per `id`. After the batch, `site` once.
